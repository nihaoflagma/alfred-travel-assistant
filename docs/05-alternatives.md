# 5. Подбор альтернатив и пересчёт плана

## Проверка расписания

Для каждого следующего сегмента рассчитывается:

`available_connection = next_departure_utc - previous_arrival_utc`

Пересадка допустима, если available_connection не меньше требуемого времени для конкретного аэропорта, терминалов, типа маршрута и способа перевозки багажа. Используется актуальная величина minimum connection time поставщика. Для отдельных билетов дополнительно учитываются получение багажа, регистрация и контроль; нельзя применять порог защищённой пересадки без проверки.

Для трансфера или активности проверяются прибытие + выход из аэропорта + время дороги + буфер относительно начала или крайнего времени услуги. Если эти данные неизвестны, план показывает риск с объяснением, а не гарантирует достижимость.

## Отбор и ранжирование

1. Зафиксировать затронутое бронирование, его пассажиров и текущую версию плана.
2. Запросить варианты до целевого пункта в согласованном временном окне. Маршрут из нескольких сегментов рассматривается целиком.
3. Исключить недостаток мест, невыполнимые пересадки, несовместимые ограничения и visa_check=FAIL.
4. Проверить багаж: ручная кладь, вес/места зарегистрированного багажа, необходимость повторной сдачи и доплата. В итоговой цене явно учесть обязательные доплаты. Если цена или условия неизвестны, отметить это и запретить подтверждение до проверки.
5. Проверить визовые условия для каждого пассажира и транзитного пункта, включая смену аэропорта и выход из транзитной зоны. UNKNOWN не равен PASS.
6. Для подтверждаемых вариантов сортировать по времени прибытия, затем полной стоимости в выбранной валюте, затем числу пересадок. Эти приоритеты — допущение MVP; предпочтения пользователя можно добавить позднее.
7. Сохранить срок действия предложения и основание рекомендаций. Перед покупкой повторить проверку.

Варианты UNKNOWN показываются отдельно как требующие проверки и не конкурируют с готовыми к подтверждению PASS в списке рекомендуемых. Если подходящих вариантов нет, сохраняется исходная бронь и предлагаются повторный поиск, поддержка и допустимые активности. Отсутствие данных об альтернативе не означает отсутствие самого рейса.

Для активности учитываются доступное окно ожидания, время дороги в обе стороны, время на повторное прохождение контроля, часы работы и право покидать транзитную зону. При неизвестных условиях выхода предлагаются только подтверждённо доступные варианты внутри разрешённой зоны.

## Пример с вымышленными данными

Три пассажира летят из аэропорта A через B в C. После задержки первый сегмент прибывает в 13:40 UTC вместо 12:00 UTC, следующий вылетает в 14:00 UTC. Для примера требуемое время пересадки — 60 минут. Доступны 20 минут, следовательно, фиксируется конфликт. Значение 60 минут иллюстративное, не универсальный норматив аэропортов.

| Вариант | Места | Прибытие в C | Проверка | Решение |
|---|---:|---|---|---|
| A1 | 3 | 18:30 UTC | Багаж включён, visa PASS, пересадка допустима | Рекомендуется первым |
| A2 | 2 | 17:00 UTC | Недостаточно мест для группы | Исключён |
| A3 | 3 | 18:00 UTC | visa UNKNOWN | Нужна проверка, подтверждение заблокировано |
| A4 | 3 | 19:10 UTC | Багаж включён, visa PASS | Второй допустимый вариант |

Организатор выбирает A1. Сервер перепроверяет цену, условия, наличие трёх мест и версию плана. После подтверждения поставщика старый сегмент помечается как заменённый, новый связывается с бронью, пересчитываются трансфер и активность. Конфликтный трансфер остаётся помеченным до подтверждения его переноса поставщиком. Если покупка не удалась, система не выдаёт новый билет за действующий.
