# Alfred — помощник при изменении рейсов

Учебный проект системного аналитика по кейсу «Альфред, друг Бэтмена». Предметная область — TravelTech, совместное планирование путешествий.

## Задача

Когда рейс задерживают или отменяют, путешественнику приходится проверять пересадки, искать замену билету и переносить остальные события поездки. Alfred отслеживает изменения, объясняет последствия и предлагает согласованный новый план.

## Результат проекта

Спроектирован сценарий от получения статуса рейса до обновления маршрута. Подготовлены требования и бизнес-правила, архитектура, модель данных, диаграммы процесса и взаимодействия, контракт API и сценарии приёмки.

Это проектирование системы: работающий сервис, реальные интеграции и измеренные производственные показатели в состав проекта не входят. Все идентификаторы и примеры вымышлены. Указанные интервалы и целевые метрики — проектные допущения, требующие согласования.

## Как работает решение

1. Адаптер получает данные о рейсе от провайдера и приводит их к единому формату.
2. Система проверяет актуальность события и пересчитывает влияние на пересадки, трансферы и активности.
3. В текущем плане обновляются сведения о рейсе и отмечаются конфликты. Пользователь получает уведомление.
4. Система предлагает альтернативы с учётом багажа, визовых ограничений, часовых поясов и состава группы.
5. После подтверждения повторно проверяются цена и места. Подтверждённый поставщиком билет включается в план; участники получают новую версию маршрута.

Автоматическое обновление фактов о рейсе не означает автоматическую покупку или отмену бронирований.

## Ключевые решения

- Запоздавшее сообщение не перезаписывает более новое состояние; время получения и время обновления у источника разделены.
- Для пользовательских действий действует optimistic locking по версии плана; конкурентный запрос получает конфликт.
- Перебронирование выполняется как асинхронная операция с идемпотентностью и сверкой результата у поставщика.
- Уведомления сохраняются в центре уведомлений; успешная отправка push не приравнивается к прочтению.
- Паспортные данные вынесены в отдельное защищённое хранилище с ограниченным сроком жизни.

## Практическая направленность

Документация позволяет обсудить границы MVP с заказчиком, согласовать контракты с разработчиками и интеграторами, а затем подготовить задачи разработки и приёмочные проверки. Ценность решения предполагается проверять по скорости обнаружения изменений, доле доставленных уведомлений и времени выбора альтернативы; фактическое улучшение этих метрик пока не измерялось.
